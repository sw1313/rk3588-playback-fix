# Decode Stack 0.7.6-test1：HEVC 十位原生显示（实验）

目标：减少实际非 AFBC 十位 HEVC 显示路径的 CPU 转换及后续 GPU 合成。
安装前为未验收候选；实机补充见后文，不宣称通用零复制或完整新版 SDK。

同一 3840×2160、30fps 十位 HEVC，配置前已有十位 profile 时原版本已经
支持 NV15 硬件平面输出，不计新增收益。配置未带 profile、请求线性输出时，
解码后才确认十位的 info-change 会触发本项目 API32 完整精度保护，切换内部
解码加 P010 CPU 拷贝，实际图层随后为 CLIENT。首次探索的期望帧数填错，
该次不算验收；正确 90 帧的未知 profile 复现完成 EOS，保留私有证据。

独立默认关闭 `hevc_native_surface`，依赖 `codec2_sdk_next` 与 `hdr_static`。
只在实际消费者含 composer、无 CPU/encoder 要求、无 tunnel／输出 crop／显式
P010 且为 RK3588 HEVC 时，保留既有 NV15 原生路径跨越 info-change。
纹理或 CPU 消费者及显式 P010/crop 保留原路径。不开启或改变 AFBC 请求，
不写像素、降低精度、绕过 fence、修改播放器或人为减少输出缓冲数量。

来源：固定 Khadas/Rockchip Codec2 提交
`e3c30156793f778541b6eaec54ac2a1ac0f6a70c` 的原生显示、stride 分配及 MPP
外部缓冲所有权。此处为针对本项目 API32 保护路径的本地选择性适配，
**不是把已有上游原生路径重复记为新增修复，也没有虚构新的上游提交**。
补丁见 `magisk-codec2-sdk-next/patches/hevc-native-surface.patch`。
上游 Apache-2.0 声明保留，现有固件／MPP／Gralloc ABI 合约继续生效。

分项关闭并重启恢复原 info-change/P010 路径；整包停用并重启恢复原固件。
新版本实机收益、完整十位样本、HDR、负向消费者和两级回退验收随后追加。
原始媒体、日志、地址、签名密钥与设备备份不进入公开包。

## 新版本已取得的路径和收益证据

已安装候选 ZIP SHA256：
`85a23fd68c752c00fbe91e11e223657201799b6bba94556f3cdbfd0c35ad569b`。
新核心 SHA256：
`2be6e10dc49fe6240caadab8fb6a1e80401d6fbf279278fd1c4ee4dd7ebb63cd`。
安装器保留实机验收过的原字节，包内候选记录是安装前快照；后补结果与源码
单独附带，不将后补文档视为另一个已经实机验收的安装器。

未知 profile／线性输出的同一 UHD 十位 HEVC，开启后 90 帧完整 EOS／停止，
逐帧跟踪 `copy=0`。实际 NV15 缓冲 stride 4864，Esmart 直接读 3840×2160，
物理输出维持 3840×2160p60。关闭后原 P010 0x36 和 CLIENT 合成恢复。
模块没有强制关闭 AFBC；线性请求由该专项诊断明确提出，符合条件的普通
AFBC 输出沿用已有压缩策略，本次不重复计为新增收益。

同一片源原压缩包流复制重复为 12 秒、360 帧，不重编码或改变源帧率。
开启／关闭均省略配置 profile、请求线性输出，均输出 360 帧、EOS、正常停止，
交付晚于计划时间 20ms 的帧均为 0。输出模式及逻辑分辨率不变。
首轮开启／关闭的整个 Codec2 服务 CPU 累计时间分别为 **0.28／4.21 秒**。
这是包含初始化和停止的进程 CPU 用时，非单独转换函数计时、播放墙钟时间、
总线带宽或游戏／所有播放器 FPS。最终重启后还要检查同一路径恢复。

收益来自该场景消除完整帧 CPU 转换和 CLIENT GPU 合成。按可见像素计算，
一帧 3840×2160 P010 写入为 24,883,200 字节；该转换取消后不再写这份输出，
相应 packed-10 源读取也取消。该字节数是路径工作量，不能当作实测 DDR 带宽
或整机内存节省。部分播放器本来采用 GPU-only 纹理输出，本开关会保留其原路径，
不宣称已经修复原播放器此前的 UHD 取帧超时。

## 新版本精度、HDR 和兼容性

用具有 composer 用途的真实 ImageReader 接收新 NV15 输出；等待 acquire fence，
从 mapper 查询平面 stride／offset，配对 DMA-BUF 只读同步，完整读取像素。
独立软件解码生成参考，逐一比较所有可见 Y／U／V 的 uint16 十位值，未用八位
PixelCopy 或“格式为十位”代替样本验收。

已开启下：普通 UHD 3 帧、含完整低位梯度 UHD 3 帧、PQ HDR 720p 6 帧均一致。
梯度样本中 27,993,600 个值低两位非零。原 PQ 720p 片段虽为十位编码，其
参考样本低两位恰为零，不能独自证明完整低位精度；因此另用上述真实十位梯度。
GPU-only 纹理和显式 P010 请求各读回 UHD 3 帧，均为原 P010 路径且样本一致，
每组各有 21,252,105 个参考值低两位非零。分项关闭后同样通过 UHD 3 帧 P010
完整样本比较。合计 21 帧、**194,918,400 个样本**，不计入旧版本验收。

专用新配置（省略 profile＋线性请求）重新执行 HEVC PQ 100、HLG 190、SDR 100
帧，暂停／恢复、flush／seek／EOS、十位 BT2020、DRM HDR blob 和静态 HDMI 包
校验均通过；退出恢复 SDR。寄存器读取不等于 HDMI 线测或最终面板低位精度。
一次重跑误用了旧 case 名，采集器读取旧报告导致失败，该次不计通过；使用全新
case 的完整专项通过。原始失败记录保留在私有目录。

Android 控制夹具 17 项和浏览器交互 59 项通过，覆盖新项依赖、保留选择、
独立关闭及“保存不等于当前启动生效”。固件／Gralloc／MPP／服务 ABI 和载荷
清单保护保留。多图层平面耗尽、旋转、热插拔、长期功耗和通用显示延迟未验收。


## 最终回退与恢复结果

分项关闭并重启后实际属性为 0，P010、CLIENT 和完整十位样本恢复；整包停用
并重启后原 HWC 和六项平台哈希一致，新增伴随库及 Codec2 插件不存在，新增
属性清空。重启后再次开启，实际属性为 1，新核心哈希与健康检查正常，
同一 360 帧负载重新为 DEVICE，CPU 累计用时为 0.27 秒。两次开启为 0.28／0.27 秒，关闭为 4.21 秒；只有一个关闭态运行，仍限于该负载。

boot、Mali 用户态／KMD／CSF、20ms DVFS 和外部 Zygisk Next/LSPosed 保持
原状态，未修改注入设置。安装及八个组件的嵌套清单、安装后保留文件、生成
载荷和实际挂载文件均通过。结论为限定路径实验通过，设备最终保持本项开启；
不是完整新版 SDK／HWC／VOP2 或所有播放器的通用升级。

历史上其他路径／样本的 HEVC HLG seek/EOS 队列超时仍未认定解决，不能用本次限定 HLG 播放通过替代其验收。
