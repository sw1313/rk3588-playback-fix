# PanVK Test8.1：地址修正与 CSF 调度对照

v0.6.9 保留原四个安装包原字节，新增一个**可选的 应用内驱动包**，不是面具模块。
Test8.1 只补齐公开许可、构建和说明，运行库与盒子上已测试的 Test8 完全一致。

已确认的问题是 RC3 将绘制辅助函数的 64 位 GPU 地址存入 `uint32_t`。函数表仍然
存活，但高位被截断，CSF CALL 访问错误地址。源码一行修正及严格限定 G610 的两条
AArch64 指令补丁均已提供；没有声称完整重编译 Mesa。

地址修正后人物恢复，但标题／按开始仍发生 `CS_UNRECOVERABLE 0x41`。强制提交同步
的 Test7 也复现，不能作为解决方案。Test8 将三个工作队列放在同一 CSF 组的三个接口，
规避疑似跨组等待问题。这个原因仍需更长对照确认；它没有更换设备 CSF 固件或内核。

保留真实 GPU 完成等待、AFBC、精确 BC 解码及 geometryStreams，不降低画质。
Android 帧交付兼容桥仍要等待真实 GPU fence，存在同步开销；删除的是 Test7 额外
增加的 `PANVK_DEBUG=sync`，不能据此声称完全异步或已优化最终性能。

验证包括 4480 组离线地址计算，编译后的 C 状态机 9000 次生命周期操作，以及设备
上的 23 项几何、17 项变换反馈、AFBC 回读和专项地址回归。游戏运行中另有 10 次真实
图形上下文创建／绘制／回读／释放通过。用户反馈人物和画面正常，标题／触摸层短测
暂未闪退；采集区间没有再见到 GPU 致命错误。**尚非长期稳定或全游戏兼容结论。**

仅实测 RK3588/G610、Android 12 API32、Linux 5.10.66，以及已有配套 g18p0 内核／CSF。
未验证原厂内核／固件或其他设备组合。游戏临时用 JIT 做对照，NCE 的另一个停滞问题
在系统驱动下也曾出现；ZIP 不会自动设置 CPU 后端，FPS 不能作为最终性能结果。

在原版应用的 GPU 驱动管理中导入并选择
`rk3588-panvk-rc3-test8.1.zip`。回退：退出游戏、选择“系统 GPU 驱动”、重新进入。
不刷 boot，不改系统驱动、Yamby、LSPosed 或解码模块。
