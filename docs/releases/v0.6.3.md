## 修改与结果

- 为匹配固件的 RK3588 AV1 原生显示 Surface 补齐无损 AFBC 输出；宽度必须为 64 倍数，继续尊重应用的 FBC-disable。其他宽度、显式 P010、Texture/CPU、裁剪输出和 tunnel 保留原路径。
- 保留来源的八位/十位精度、HDR 和 signaled film grain。修复八位识别后错误切换布局引起的启动失败，并根据完成帧的真实偏移处理顶部填充。
- 同一 60 秒原始 AV1 3840×2160、60000/1001 fps、十位 PQ/BT.2020、Opus 本地文件，开关对照从丢 2434 帧变为零丢帧。最终二进制渲染 3597/3597 帧，收到 3597 个呈现回调，没有超过 25ms 的间隔；回调时间戳不能冒充物理显示器测量。
- 同路径原型另测约 314 秒：18808 帧全部交付、播放器零丢帧。它在最终宽度保护和逐帧裁剪补齐之前测试，与最终二进制的 60 秒结果分别记录。
- 五组 AFBC 样本（十位、有/无颗粒、UHD、真实片源及八位 4096×2160）解压后与软件参考逐像素一致；另六组 Codec2 基础格式精度一致。没有宣称完整长片逐像素校验。
- 保留 `av1_afbc`、`av1_native`、`av1_grain` 等分项开关、依赖处理和整包回退；均需重启生效。原厂回退核对 31 个系统文件，重新启用通过。暂停、继续、前后 seek、EOS 及 HDR/HLG/SDR 回归已完成。

本发布还包含自 0.5.1 起的累计源码：完整十位转换的 SIMD/批量写入、Codec2 1.14.16/API32 移植、原生 AV1 显示/P010 输出选择及 AV1 胶片颗粒恢复。MPP 可缓存概率表、异步输出补充等未改善播放的试验不包含在运行包中。

## 安装、兼容与限制

仅接受契约匹配的 RK3588 Android12/API32 固件及原厂 5.10.66 内核。在 Magisk 安装 Decode Stack ZIP 并重启；旧独立 MPP/RGA/Codec2/libyuv 模块保持停用。已使用其余三个组件的用户无需重装它们。

```sh
sh /data/adb/modules/rk3588_decode_stack/mode-control.sh av1_afbc off
sh /data/adb/modules/rk3588_decode_stack/mode-control.sh av1_afbc on
sh /data/adb/modules/rk3588_decode_stack/mode-control.sh all off
```

关闭 AFBC 恢复原来的线性输出，保留源位深；关闭整包并重启恢复原厂组件。不热替换运行中的库，不刷 boot，不更换内核或提高频率。Yamby 原版组件和 LSPosed 0.3.3 未修改；本次没有新增 Yamby 人工验收记录。

- 真实播放改善针对上述片源和路径，不保证所有 AV1、网络播放或其他固件。八位 4096×2160 的短片仍测得 6 帧丢帧，不能描述为所有格式零丢帧。
- 非对齐宽度、Texture/CPU 和旧 ExoPlayer 的 AV1+Opus/MP4 时钟情况仍有既有边界；本地 WebM 测试没有修改媒体包、PTS、丢帧阈值或评分。
- 安兔兔完整剪辑提前 EOS／固定帧数等待及图像特效退出崩溃仍未修复。
- HDR10+ 仅指已有标准 Codec2 元数据桥；没有新增 HDMI HDR10+、Dolby Vision/LLDV/FEL 或内核 VPU 驱动升级。

This complete release updates only Decode Stack. Its guarded lossless AV1 AFBC route preserves source precision, HDR and grain. Final-binary local 4K60 HDR playback rendered all 3597 frames with zero player drops; prototype long-form evidence and finite pixel tests are separately qualified. Firmware contracts, feature switches and reboot rollback remain. Yamby, LSPosed, Mali, boot and kernel are unchanged; unrelated benchmark failures remain unresolved.
