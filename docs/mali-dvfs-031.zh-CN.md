# Mali Global 0.3.1-test1：可回退的 GPU 动态响应

本轮继续原计划中的 GPU DVFS 方向，把“GPU 动态响应”集成到现有 Mali Global：WebUI、依赖控制、固件检查、启动生效和重启回退均在同一模块中。它是调频响应策略改进，Mali 用户态、内核驱动和 CSF 的版本及二进制保持 0.3.0 的已验证组合。

## 改动

当前配对内核的源码默认 `polling_ms=100`，实机 `simple_ondemand` 节点同样是 100ms。新增选项在新版内核/CSF 完成资格检查后，把 GPU 负载检测周期改为 20ms，让突发绘制负载有机会更早触发原调频器。它只在启动时写入一次，不运行持续调频守护进程。

安装包默认关闭。开启会补齐全局 Mali 用户态及配对 next 内核/CSF；关闭上级保留该项选择并抑制生效。仅支持既有固件合约、RK3588/API32/5.10.66、原调频器及已识别的检测周期。其他调频器、外部自定义周期及未完成内核资格检查会跳过，WebUI 显示未应用，不能仅凭保存成功显示已生效。

该选项保留原 OPP、300–900MHz 调频范围和温控限频。不锁频、不超频、不修改电压，不改变渲染分辨率或着色器工作量，也不跳过同步。相比 100ms，20ms 会提高潜在的轮询频率，长期功耗及温度尚需专门测量，因此保留实验标记。

## 验证方法

新增独立的有界 GLES3 离屏负载：每组绘制 12 帧固定 512×512 着色器，每组开始前空闲 800ms。每帧都 `glFinish` 等待完成、检查 GL 错误并读取相同 8×8 RGBA 区域。每次像素摘要应完全相同，不能靠少做工作获得更低耗时。

`draw+finish` 耗时包含驱动及 CPU 调度，不是 GPU 硬件时间戳；整组墙钟时间还包括节点读取和回读检查。首帧、起始频率、温度和离群值保留在私人原始记录中，不把这项诊断写成游戏跑分或视频流畅度。

前期同一次启动的 100/20/100/20ms 交替探索，每档每轮 12 组。100ms 两轮的整组 `draw+finish` 中位耗时分别约 180.0 / 132.7ms，20ms 为 97.2 / 94.4ms；首帧耗时没有明显改善，且各轮有波动。模块安装后的独立启动验收结果见随包 `VALIDATION.json`，不只以这组探索作为模块验收。

实际模块在两次完成资格检查的启动中，分别运行同一负载 24 组、288 帧：

| 指标 | 关闭，100ms | 开启，20ms |
| --- | --- | --- |
| 整组 draw+finish 累计耗时中位数 | 181.57ms | 97.24ms |
| 整组墙钟耗时中位数 | 182.77ms | 98.24ms |
| 首帧耗时中位数 | 16.724ms | 16.720ms |
| 每帧 8×8 回读摘要 | 2464417444 | 2464417444 |
| GPU 温度，开始 → 结束 | 42.5 → 41.6°C | 41.6 → 41.6°C |

在这组特定负载中，累计耗时中位数减少约 46.4%，首帧基本不变。全部组均纳入统计；只比较起始 300MHz 的组时，关闭/开启分别为 181.59 / 97.46ms。仍有离群组，20ms 模式最慢组约 182.1ms，所以不保证每次突发都更快。该结果不能换算成游戏帧率或视频提升百分比。

独立关闭、重启后实际节点恢复 100ms，WebUI 显示该项关闭且无待重启，g18 用户态和配对内核保持启用；重新开启也需重启及完整内核资格检查。

32/64 位 GLES、Vulkan 在 20ms 实际生效后完成精确像素/缓冲回读。控制层通过 37 项隔离 Android shell 检查，WebUI 通过 22 项交互检查，包括依赖补齐、保留选择、不立即改动运行策略、异常输入和外部策略识别。原有 GPU 库和内核 `.ko` 与上一模块逐字节一致。

## 使用和回退

在 Mali Global 的 WebUI 开启“GPU 动态响应（实验）”，保存并重启。也可使用：

```sh
sh /data/adb/modules/rk3588_mali_global/mode-control.sh dvfs on
# 重启后生效
sh /data/adb/modules/rk3588_mali_global/mode-control.sh dvfs off
# 重启后恢复驱动默认 100ms
```

关闭该项保留 g18 用户态和配对内核/CSF。选择原内核会同时抑制此项；整包关闭并重启仍恢复原固件。启动期间只等待本地模块检查，不依赖电脑、ADB 或网络确认。

## 范围和后续方向

这项不代表所有游戏 FPS 提升，也没有解决此前原版播放器 UHD HDR 的取帧超时。Decode Stack、十位/HDR 转换实现和原版应用不在本次运行代码改动范围，不能把旧播放验证记为本版新增验收。

原计划中的 MPP reset/seek 修正、RGA 1.10.6、libyuv 溢出修正已在现有构建；不重复计为新增升级。HWC2/VOP2、HDMI 刷新率及 VPU 内核补丁仍需具体代码和兼容性证据，尚未集成，不能因为本项通过就标为全部方向完成。

源码与候选模块仅在本地交付，尚未发布正式版本；原始设备日志、地址、固件原库、媒体及签名密钥不进入公开包。结构化结果见 [验证记录](validation/mali-dvfs-031.json)。
