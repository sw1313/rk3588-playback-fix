# Decode Stack 0.7.5-test1：缩放图层硬件合成资格修正

对应原建议第 1 项：减少不必要的客户端 GPU 合成，让符合条件的图层进入
VOP2 硬件平面匹配。本项的验收是目标图层 CLIENT→DEVICE、真实 DRM 平面
接管和相同内容的兼容性；HDR 元数据对象复用不算这项目标的收益。

## 来源、原库核对及实际改动

Rockchip 提交 [`e3e3d168e524da25620ef55da734e48c8e56afe6`](https://github.com/TinkerBoard-Android/rockchip-android-hardware-rk35-hwcomposer2/commit/e3e3d168e524da25620ef55da734e48c8e56afe6)
在 RK3588 的 `CheckGLESLayer` 删除两条沿用自 RK356x 的无效缩放排除条件：
非 AFBC、水平放大时，源有效宽度 `%16==1` 或目标宽度为奇数。
本机 HWC2-1.3.8 的 ARM64 方法仍实际包含两条判断，未重复移植已有修复。

本地配套：安装器仅接受 SHA256 `ec3e42d1…` 的原伴随库，从它生成私有变体。
文件／VA `0x85dc8` 的一条 `cbz w8,+0x64` 指令跳入两条排除判断，将其替换为
NOP，令该路径与上游删除这两条判断的行为一致。完整输出哈希必须为
`47702a172f0b95ecc88dbc60a9b42a09b80841e9b4269ce74d7af916af33901b`。
仅四字节不同，最小宽高、无效变换、纯色及 CLIENT 图层其他条件均保留。
补丁不将图层直接标成 DEVICE；后续原平面匹配、格式／缩放能力与提交仍由原 HWC 决定。

独立进程以真实原库与变体方法执行 768 组资格检查，20 组过时拒绝变为允许，
其他条件和全部输入字节保持一致。该检查没有打开显示设备，不能代替实机平面验收。

## 集成与回退

新增 Decode Stack 的独立默认关闭 `hwc_scaled_overlay`，依赖现有 HDR 适配层。
安装器生成并核对私有变体；开机组装时才按选择覆盖伴随库，生成相应活动哈希。
保留完整原伴随库，关闭并重启恢复原字节；整包停用恢复原固件。支持中英文
WebUI、依赖补齐、当前／下次启动状态和启动失败回退。

HWC HDR 适配器、Codec2、MPP、Gralloc、Mali 和 boot 的运行代码不为该策略改动。
不写运行中 HWC 的代码页，不改像素、位深、缓冲尺寸、源帧率、fence 或播放器统计。
原 HWC／私有变体、设备日志、影片和测试签名密钥不进入公开包。

这是限定原厂 ABI 的选择性回移，整套最新 HWC 的兼容性尚未确认。HWC 版本字符串
保持原厂值；组件包版本号不作为整套 HWC 或 VOP2 内核升级的证明。

## 安装前记录（历史快照）

新开关和源代码已集成，安装前仍为未验证候选。原 641×360 线性 RGBA 图层
放大到相同物理 3840×2160 场景已观测为 CLIENT，由 GPU 先合成到全屏 AFBC 目标。
现有 HEVC AFBC 视频则本来就在 DEVICE 平面，不计为本补丁的新收益。
具体新版本实机结果随后补充，未通过前不标记为完成或可发布。

## 新版本实机验收范围

已安装的有效候选是 `rk3588-decode-stack-0.7.5-test1.zip`，SHA256：
`83b8deba9f6b8acfa50f0d0aa99d3dd21e0cbd4b0e895573772058b6d9ee82ee`。
初次安装因组件脚本相对路径失败，旧模块仍正常活动；修正绝对路径后的第二包
安装及重启成功。失败包不计入交付。有效包保持原字节，包内候选状态为安装前快照，
以本专项记录和同名 JSON 补充实机结论，不覆盖重打包原安装器。

实际路径：原厂策略使 641×360 线性 RGBA 动态图层 CLIENT 合成，由全屏
3840×2160 AFBC 客户端目标扫描输出；开启分项并重启后，同一尺寸和内容为
DEVICE，Esmart0 直接读取原 641×360、stride 2624 缓冲，放大到相同
3840×2160p60。没有改变逻辑窗口、输出刷新率、源图像或 fence。
普通 AFBC 视频原本已能 DEVICE，未将它记作新增收益。

原 HWC 的静态画面缓存策略仍保留，生产者停止后可能切回 CLIENT/cache；
结果仅覆盖正在更新的目标图层，不承诺所有 App、图层组合或缩放比例。
两条限制均通过真实旧／新方法的隔离检查；实机已触发源宽 `%16==1` 路径，
奇数目标宽视频尝试实际被取整，未记作奇数目标宽的实机通过。

新版本开启下重新运行十位 AV1 grain：854×480、24fps、240 输入及输出帧，
完整 EOS/停止，DRM 为线性 NV15 Esmart 十位路径。另跑 HEVC PQ 100 帧、
HLG 190 帧、SDR 100 帧，共 390 帧，暂停／seek／EOS、HDMI 十位 BT2020、
DRM blob 和 HDMI 静态包及退出恢复 SDR 均通过。关闭后 PQ／SDR 200 帧亦通过。
这些是新版本路径及元数据兼容性证据；八位 PixelCopy 不能验证十位低位精度，
寄存器读取不代替外部 HDMI 线测或最终面板画质测量。

分项关闭并重启恢复原伴随库完整 SHA256；整包停用并重启恢复原 HWC、六项原平台
文件哈希，并移除注入的 HWC 伴随库及 Codec2 插件。重新启用后精确变体和启动健康
检查恢复。boot 未写入；Mali g18 首次绑定、20ms DVFS 及外部 Zygisk Next/LSPosed
保持正常，不修改注入设置。安装前固件备份仅私有保存。

## 合成与软件延迟 A/B

同一 APK，CPU Canvas 每次实际提交 1200 帧，均约 20.000 秒完成；启动后预热
6 秒，再采集约 8 秒 TimeStats。采样时生产者仍更新。逻辑窗口 1920×1080，
物理输出维持 3840×2160p60；两次源 PixelCopy 960×540 的八位像素逐一相同。
环境允许现有投屏连接保留，结果只适用于该设备当时负载，非隔离平台跑分。

| 指标 | 分项关闭、重启 | 分项开启、重启 |
| --- | --- | --- |
| 目标图层 | CLIENT | DEVICE |
| SF CLIENT 合成帧／总帧 | 488／488 | 0／490 |
| missed frame | 0 | 0 |
| SF averageFrameDuration | 2.100ms | 1.022ms |
| post→present P50 桶 | 32ms | 32ms |
| post→present P95 桶 | 33ms | 32ms |
| latch→present P50／P95 桶 | 15／15ms | 15／15ms |
| present→present P50／P95 桶 | 16／16ms | 16／16ms |

post→present 样本分别 486／488。SF 帧处理统计下降且 CLIENT 合成消除，证明该
场景减少合成工作；它不是应用端到端或光学显示延迟。中位数不变，P95 仅差一个
毫秒桶，没有重复独立样本支持稳定延迟收益，**显示延迟改善未通过验收**。
TimeStats 的 16ms 桶不能推算成真实 62.5fps；实际显示模式仍为 60Hz。
关闭态 DRM 快照还捕获到一个小的瞬时平面，SF 采样时只有目标图层；未把
该瞬时平面计作补丁前后工作量收益，延迟结论保持上述保守范围。

WebUI Android 独立夹具 14 项、浏览器 57 项通过；安装器及八个组件嵌套清单、
安装后保留文件、生成载荷及实际挂载清单均核对。结论为限定场景实验验证，
不是通用稳定版或优先级 1 整项完成。

## 完整 HWC 与 VOP2 的状态

完整 HWC 可继续适配，但当前仅交付上述明确提交的选择性修正，HWC 字符串仍为
原厂 1.3.8，未宣称最新 HWC 已升级。整库替换还需对齐 Gralloc 私有句柄、DRM
属性／平面能力、HDR、HWC2 服务 ABI、SELinux 和板级配置。

当前 `CONFIG_DRM_ROCKCHIP=y`、`CONFIG_DRM_DW_HDMI=y`，VOP2/HDMI 为内建，
不能作为 `.ko` 直接替换。原镜像与配置不等于匹配的可构建厂商源码；本轮没有
VOP2 内核代码、设备树或 boot 改动，也没有可验收的 VOP2 升级包。
