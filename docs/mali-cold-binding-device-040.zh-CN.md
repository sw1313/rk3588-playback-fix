# Mali Global 0.4.0-cold1：本机启动与回退验证

**撤回该候选：后续发现 Zygisk Next 注入失败。此前启动资格检查漏验了 Zygisk，
不能据以下图形检查宣称与既有注入模块兼容。修正已转入 0.4.1-test2，结果见
[Zygisk 修复验收](mali-zygisk-repair-041.zh-CN.md)。以下保留旧版历史记录。**

日期：2026-10-18。对应 Decode Stack 0.7.2-cold2；使用此前批准的安装包与私有
root boot 候选，测试期间没有改动驱动、解码或显示二进制。**有限实机验证通过，
仍为实验候选，不作为稳定版发布。**

## 实际确认

旧 Mali 对应初始化入口在内核日志中确认被 blacklist。加载器在 GPU 尚未绑定、
分配器／HWC／SurfaceFlinger／两个 Zygote 尚未 exec 时加载 g18 KMD，再放行
原始进程；三次启动分别在 CLOCK_BOOTTIME 约 7.80、7.73 和 7.58 秒放行。这是本次
启动的记录，不能与旧日志不同时间基准直接相减，也不代表游戏帧率或总开机耗时。

五个原始服务 PID 在资格检查和 HDR 播放后保持不变。冷启动分支没有调用旧的
运行中交接控制器，没有主动停止／重启这些客户端。ARM32／64 GLES 与 Vulkan
精确回读，以及配套 CSF、框架、音频和 GPU 响应策略的启动检查均通过。

三项回退实测通过：

- 关闭首次绑定开关：写回并核验原 root boot，重启后由原内建 GPU 驱动绑定，
  新 KMD 不再加载，GPU 轮询恢复原 100ms。
- 整包停用：模块脚本不执行的情况下，独立 ramdisk 加载器检测停用，恢复原
  root boot 并再重启；原 GPU 用户态校验通过，新 CSF 覆盖路径消失。
- 注入“上次启动未确认”的持久标记：下次启动在加载新 KMD 前恢复原 boot，
  自动重启回原驱动；显式重试能清理旧失败标记并重新选择候选。

保留现有 root、原始完整 boot 以及模块和设置备份。未实际制造内核硬挂、写入中断
或物理断电；没有宣称这些极端情况下必然能通过 ADB 恢复。实际管理器卸载删除
未测试，不能用整包停用冒充卸载验收。

## 新启动路径下的图像检查

同一 Surface 的五项场景通过暂停、seek、EOS 和退出：HLG、PQ 1000-nit、
PQ 4000-nit、无 mastering metadata 的 PQ、SDR。HDR 场景观察到十位 BT.2020，
DRM HDR metadata 与 HDMI 软件 InfoFrame 对应，退出恢复 SDR。没有线缆仪器或
光学测量；HLG 的 PixelCopy 不支持结果不作为图像精度证明。

AV1 十位 AFBC 实际缓冲区通过原有 RGA 探针解压后，4 帧、12,441,600 个采样值
与参考完全相同；其中 9,326,614 个值的低两位非零，范围 0–1023。这验证有限
解码缓冲精度，不等同于最终 HDR 显示或播放器 tone mapping 的完整精度。

## 必须保留的异常与限制

首轮 HEVC HLG 的一次 seek／EOS 附近出现 Codec2 queue timeout，继而在
releaseOutputBuffer 抛 IllegalStateException。后续冷启动重试和原启动路径的
同片对照未复现。**原因未定，不归因为 Mali，也不宣称已修复。** 原始失败记录
保留在私有测试目录，未从结果中删除。

初次 HDR4000 采样用了 640×360 素材配合直通断言，原启动路径也出现相同 SDR
观察。更正为此前的 1280×720 直通素材后验证通过；没有修改产品分辨率、位深、
帧率、fence 或播放器统计。该错误测试不计入直通通过场景。

未进行游戏长测、功耗长测或所有播放器兼容认证。原有投屏干扰条件不作为已排除
条件；这次没有用吞吐或帧率对照宣称性能提升。

初始候选包内的“未实机验收”记录描述构建时状态；本文件和
[机器摘要](validation/mali-cold-binding-040.json) 是后续设备验证补充。运行代码与
已批准安装包保持一致，原始日志、镜像、影片和设备标识不进入公开记录。

最终设备已恢复首次绑定开启：Mali Global 0.4.0-cold1、Decode Stack 0.7.2-cold2、
g18 KMD／CSF 与 20ms 响应策略均 active，无待重启设置。16 个关键运行文件与批准包
哈希一致，Decode 分项选择与安装前备份一致，实际 root 权限仍可用。
