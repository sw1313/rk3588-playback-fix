# Mali Global 0.3.0：配套内核／CSF 与重启控制

本版把已完成实际接管的 g18p0 内核驱动和配套 CSF 纳入现有 Mali Global 模块。原有全局 32／64 位 g18p0 用户态保留；新安装默认使用原内核／CSF。它只支持合约匹配的 H96 Max V58／RK3588、Android API32、5.10.66 固件，并非通用刷机包。

## 使用

在 KsuWebUI 或兼容管理器中打开 Mali Global，选择“g18p0 内核＋配套新版 CSF”，保存后正常重启。上级是全局 Mali 用户态，下级是配套版本选择；关闭上级保留原下级选择并灰显，选择新版组合则补齐用户态依赖。页面区分当前和重启后的状态、检查结果、待重启及回退提示，English／中文按钮会保存语言。

内核与 CSF 是配套组合，不允许任意混搭。保存只修改下次启动配置，不立即操作正在使用的 GPU。启动时先正常使用原内核，在用户态及原有解码初始化验证完成后短暂重新加载桌面并接管 GPU。采用保留音频、停止图形客户端、重建 HWC 的已验证顺序。

## 失败保护与回退

切换前先落盘保存本次尝试标记；本地健康检查与 32／64 位 GLES、Vulkan 绘制验证通过后才清除。健康检查不依赖电脑确认、ADB、网络或互联网。独立守护进程对可恢复失败最多请求一次普通重启，并选择原内核；若中途断电或启动未完成，下一次启动跳过新版组合，保留用户态升级。

单独回退：选择“原内核＋原 CSF”后重启。整套回退：关闭上级或在管理器停用模块后重启。完全内核卡死仍可能需要断电，用户态守护进程不能保证硬件级恢复。不刷 boot，不写真实系统分区；原内核／CSF 随重启恢复。

## 测试范围

安装后的真实启动矩阵已验证：默认原内核、整套关闭及保留下级选择、新版组合接管、单独内核回退、模拟未完成启动保护、再次启用新版组合。最后状态为新版组合启用、健康检查通过、无待重启。

两种架构均通过 GLES 着色绘制和精确像素回读、Vulkan 填充和 4096 字节精确回读；已确认实际内核绑定、CSF 摘要、音频进程保留、供电桥释放、旧回调恢复及固件搜索路径恢复。boot、原厂 CSF、Decode Stack、Yamby 原版库和 LSPosed 保护哈希未变。此前同一接管基线已有游戏和 HEVC 十位人工确认；本次安装模块启动矩阵并非对所有应用的重新验收。

这不包含完整 CTS、长期功耗或任意设备支持，也没有证明所有隐藏引用都被排空。现有安兔兔剪辑完成／图像特效退出问题不在本次修复范围。详见 [脱敏验证记录](mali-kernel-068-validation.json)。

## 源码与许可

内核驱动及交接助手按各文件 GPL 条款发布，完整冻结驱动、兼容头、构建配置和助手源码位于 `mali-kernel/`。安装器和 WebUI 自写代码保持 MIT。闭源 Mali 库和 CSF 在安装时另行下载并严格校验尺寸／SHA256，不放进公开 ZIP。其余三个安装包沿用 v0.6.7 的原字节及源码声明。
