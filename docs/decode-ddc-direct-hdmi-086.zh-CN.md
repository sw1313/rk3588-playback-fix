# Decode Stack：直连 HDMI 的 EDID 修复与初始化

最新后续：用户要求同时打开 QMS 与 GPU 十位 HDR 合成。已恢复既有冷启动配置，并将原厂显示初始化提前到 QMS 首次绑定之前；两项已实际加载，Mali／注入／直连链路检查通过。桌面 SDR 仍为 8-bit，真实 HDR 输出和短黑待播放验收。见 [本轮启用记录](validation/qms-hdr-direct-enable-086.json)。下文 QMS 未加载配置为此前基础显示／音频对照快照。

## 当前结论

LG C5 直连 HDMI1 的原始 EDID 共 512 字节。原厂内核将块 2／3 错读成块 0／1，虽然块校验和均正确，实际 CTA／DisplayID 能力丢失，原厂将电视识别为 DVI。原始 Image 反汇编确认分段指针缺少左移 7 位，读命令缺少按分段切换 EXT_READ。

已将对应修复集成到 Decode Stack `0.8.6-qms-test14-ddc1` 的 `display_ddc` 项。实际加载后，原厂 DRM 及 i2c-dev 两条路径均可读取正确的四块数据；原厂完整显示重建后，用户确认 HDMI1 有信号，接收端时钟／三通道锁定。仅刷新能力缓存不足以修复先前 DVI 状态留下的输出配置，因此增加开机一次性的原厂显示初始化。

这仅是直连基础显示修复。短黑未修复；HDR／十位／QMS 组合未通过本候选验收。当前已观察到的正常输出为原厂重新协商的 4K60 YUV420 8-bit SDR；组件没有硬编码该格式，也没有把它标为完整 HDR 成果。

## 实现和回退

- `rk_decode_ddc.ko`：只替换已核对的原生 HDMI I2C 适配器算法指针。标准分段 EDID 事务改用正确指针位域和 EXT_READ；其余 EDID／SCDC／HDCP 操作委托原算法。支持 i2c-dev 自动添加的 DMA_SAFE 标记。
- 发布前核对完整原厂 QP 事务、IRQ 代码指纹、算法表、对象关系、头文件布局、导出 CRC 与模块 vermagic。没有代码段补丁、EDID 覆盖或强制电视能力。
- 使用 I2C 根总线锁发布，复用原生互斥锁和 IRQ completion；发布后保留模块和适配器引用，重启回退。
- `rk_decode_ddc_recover.ko`：在 QMS owner 未加载时，开机一次通过原厂 DRM 全锁／atomic 检查及完整 modeset 重建相同逻辑时序和图层缓冲。允许原厂依据真实 EDID 重新选择链路格式，不强制降低分辨率、帧率或位深，不替换 fence。
- 初始化核对逻辑模式、图层缓冲、供电和 VOP 基础时序，要求 VTEM 关闭。原厂 AVI／音频等包使能可因 DVI→HDMI 纠正而变化；这一例外只适用于该专用初始化模块，不修改 QMS 原有提交门禁。
- `ddc-state.sh` 保存分项启动状态；上次未确认启动时仅关闭 `display_ddc`。初始化最多一次，不因失败无限重试或自动循环重启。启动确认与实屏验收分别记录。
- `sh /data/adb/modules/rk3588_decode_stack/mode-control.sh display_ddc off` 后重启恢复原厂读取路径。整包停用并重启同样恢复。已有整包私有备份；不改 boot 或其他模块标记。

## 自动暂停／无声：独立记录

直连恢复画面后，用户反馈 Exo 仍短黑、进入播放自动暂停和无声。日志显示模式重建期间连续 extcon false／true，Android 随后广播 `AUDIO_BECOMING_NOISY`，音频策略反复拆除／重建 HDMI 输出；该时刻音频焦点仍授予播放器。自动暂停有明确系统事件触发链，恢复已有系统层过滤并重启后，用户确认自动暂停和无声均不再出现；该场景通过，短黑单独未通过。

当前 `hdmi_audio_guard` 原为关闭。随后恢复 Decode Stack 中已有的系统层瞬态 extcon 修复；它只在独立 DRM 连接状态持续为 connected 的短窗口合并假拔插，真实断开不作已连接处理。没有恢复 Frame Guard，没有修改播放器的暂停行为或直接发送输入事件。旧功能恢复不计为新增升级。

本轮实际启动配置：`display_ddc=1`、`hdmi_audio_guard=1`、`display_qms=0`、`display_policy=1`，Frame Guard disable／paused。工作期间保存选择出现变更，保留用户现有选择。QMS 的下一次启动请求为 1，但当前原 GPU 内核启动没有 QMS 冷绑定屏障，实际 owner／端点未加载；勾选不等于已经启用。先验收基础启动和声音，不能以这组配置宣称 Auto/QMS 短黑已通过。

## 上游来源及验证边界

厂商提交 `cdc0984c90dc`（`drm/bridge: synopsys: dw-hdmi-qp: Support read ext block edid`）的两处修改由原开发者在[邮件](https://lkml.iu.edu/2406.0/06496.html)中明确列出。本地采用算法适配器回移，未替换整套 HDMI／VOP2 内建驱动。

构建已检查修复模块 18 个、初始化模块 46 个标准模块版本条目。实机完成只读加载／卸载、分段读修复、未确认启动的分项回退、用户手动确认恢复信号。最初临时加载未写启动确认就重启，曾触发分项回退；已保留日志并纠正试装流程，不将其称为内核崩溃。

此前研究用全恢复检查在提交成功、模式和缓冲保留后，最终身份检查返回 ESTALE；不能将 insmod 返回非零误称为没有执行过提交，也不能把该检查计为全项通过。专用初始化候选把 EDID 纠正允许的原厂包重新协商与 QMS 严格保持检查分开，已在后续真实启动通过：提交约 235ms，逻辑模式／缓冲保留，原厂包使能由 `0x00000000` 更新至 `0x00002008`，VTEM 未启用，初始化模块正常卸载，接收端三通道锁定。用户随后反馈“只有短黑了，其他都正常”：本次重启自动出画面、进入 Exo 不再自动暂停且声音正常，短黑仍未通过。
