# Decode Stack 0.6.5：版本单选与依赖联动

打开 **KsuWebUI → RK3588 Decode Stack**。原来独立的 SDK 和 1.14.16 开关
合并为一个“Codec2 后端版本”下拉框：

| 选择 | 实际后端 |
| --- | --- |
| 旧后端（0.4.0 路径） | SDK 移植前保留的兼容后端，不等于原厂 Codec2 |
| 1.14.3 SIMD | 保留的完整精度 SIMD 后端 |
| 1.14.16 | 当前新版后端 |

这三个版本互斥，不会同时加载。关闭上级“Codec2 兼容层”并重启，才会恢复原厂
Codec2。其他独立系统组件仍按其自身选择工作。

## 依赖与保存

下级直接接在对应依赖项下面，用缩进与连接线表示层级：MPP 下是颗粒修正和
Codec2，Codec2 下是后端版本及软件解码、十位转换和 HDR；后端版本下是
八位缓冲区修正、AV1 原生输出，AV1 原生输出下是 AFBC。
Codec2 另需 RGA，卡片会同时列出这个额外依赖。

- 关闭父项：下级保留原选择，卡片和已保存开关变灰，标明暂不生效。
- 重新开启父项：按保留选择恢复，下级无需逐个重新打开。
- 开启子项：一次性补齐所需依赖，并显示联动修改的项目。
- AV1 原生输出／AFBC 需要 1.14.16；开启时会联动选用该版本。
- 手动选择三个后端之一：补齐 Codec2、MPP、RGA；较旧版本会暂时抑制不适用的
  AV1 路径，但不会清除其原选择。
- 整包停用时仍能编辑分项选择；分项操作不会擅自重新启用整包。

灰色表示依赖未满足或整包关闭，保存选择仍可编辑。“当前”和“重启后”继续分开显示；
保存设置不会热替换运行库。旧 CLI 单项命令保留原有的独立写入行为；WebUI 使用
`linked` 联动命令。`codec2_backend legacy|simd|latest` 是版本选择入口。

版本的两项底层标志及依赖补齐通过同一次临时文件写入／rename 提交，避免两次
命令之间留下半套版本选择。参数仍为固定白名单，配置只作数据处理，不执行其内容。
升级暂存同步、固件契约、Action、启动装配和健康检查回退不变。
