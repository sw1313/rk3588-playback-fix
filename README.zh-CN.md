# RK3588 Playback Fix · v0.8.6

这次正式版解决指定 Exo 场景在 Auto 下暂停／恢复／同片快进时反复清除片源帧率请求的问题。系统会先匹配视频帧率，播放期间保留该视频图层的匹配结果，新帧率请求正常更新，退出后不再采用已隐藏或移除图层的请求。修复集成在 Decode Stack，覆盖系统旧入口和 BLAST 事务，适用于走这些接口的应用。用户已在 HDMI 实屏确认该场景可以了。

[下载完整更新](DOWNLOADS.md) · [正式发布页](https://github.com/sw1313/rk3588-playback-fix/releases/tag/v0.8.6)

| 组件 | 版本 | 本版作用 |
| --- | --- | --- |
| Decode Stack | 0.8.6 | 系统帧率保留、原生队列稳定性和已记录的十位／显示兼容修复 |

| Frame Guard | 0.1.1 | 原包保留，用于可选固定刷新率规避；Auto 内容匹配时关闭 |
| PanVK | RC3 Test8.1 | 原包保留，仍是应用内可选实验驱动，不影响全局驱动 |

WebUI 中按用途整组选择，也可展开分项。升级保留既有选择，依赖关闭时灰显但不丢失选择；“当前”与“重启后”分别显示实际和保存配置。所有组件替换通过重启完成，关闭分项恢复对应旧路径，关闭整包并重启恢复原固件。

QMS 用来处理真正发生的同分辨率变速，帧率保留用来减少暂停时不必要的来回切换，两者互补。首次绑定和低层 QMS 需要针对当前固件／root 单独准备私有启动配套，未准备时不可启用；公开包不包含 boot／原固件。完整 HDR 校准、真正换分辨率或 HDR 信号格式、所有接收端及长期游戏收益仍不由这次验收推定通过。

适配限定契约精确匹配的 RK3588 H96 Max V58、Android 12/API32、5.10.66 固件；不是所有 RK3588 设备通刷包。Mali 闭源驱动与 CSF 通过固定来源和哈希下载，不打包分发。源码、许可与每项已验收／剩余范围均有记录。
